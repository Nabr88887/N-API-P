# 门户访问事故记录：本机 SSH 隧道未运行

- **日期：** 2026-11-09（Asia/Shanghai）
- **范围：** 内部 N-API-P 门户的本机访问路径
- **状态：** 已定位，待纳入明日启动检查

## 现象

浏览器无法打开内部门户的 `:18443` 地址，导致门户访问问题被长时间按服务器故障
排查，浪费了大量时间。它与 Gate C 的 NewAPI HTTP 后端问题是两个独立阻塞，不能
合并成一个根因。

## 核验结果

- 本机 hosts 解析将门户域名指向 `127.0.0.1`。
- 本机没有运行中的 SSH 隧道进程，也没有本地 `18443` 监听端口。
- 服务器侧 proxy 容器仍在运行，服务器回环地址 `127.0.0.1:18443` 正在监听。
- 通过严格 known-host SSH 在服务器侧检查，门户 `/`、`/health/live` 和
  `/health/ready` 均返回 HTTP 200。
- 未修改服务器配置、未重启服务、未访问认证内容。

## 根因

该访问方式依赖本机 SSH 本地端口转发。隧道关闭后，浏览器仍通过 hosts 解析访问
本机 `127.0.0.1:18443`，因此连接失败；这不是服务器门户服务故障。

## 明日启动检查

1. 先读取 `.codex/LOCAL-DEPLOYMENT.md`，确认记录的 SSH identity、known-host
   约束和本地转发命令。
2. 启动本机 SSH 隧道并保持 PowerShell 窗口运行。
3. 先用只读的 `/health/live` 和 `/health/ready` 验证转发，再打开浏览器。
4. 若本机仍无法连接，分别检查本机 `18443` 监听、SSH 进程和服务器回环监听，
   不要先修改 DNS、hosts、Nginx 或服务器配置。
5. 门户隧道恢复后，继续处理 Gate C 的 NewAPI 后端 HTTPS 阻塞；两者是不同问题。

## 复用约束

- `localhost` 或 hosts 指向 `127.0.0.1` 的内部域名不代表公网服务。
- 本地门户连通性检查必须先确认隧道状态，再判断服务器故障。
- 本记录不包含域名、SSH identity、凭据、Cookie、Token 或业务数据。
